● Đây là toàn bộ luồng xử lý của repo, từ input CSV đến output cuối, theo đúng
  thứ tự thực thi trong main.py:run().

  0. Khởi động & input

  - main.py tự tìm file input: ưu tiên INPUT_CSV env, nếu không có thì quét
  data/public_test*.csv → private_test*.csv → bất kỳ *.csv nào trong data/.
  - Đọc CSV, normalize_row() chuẩn hoá: nếu có cột choices (dạng JSON list
  ["A","B","C","D"]) thì convert sang cột A,B,C,D để tương thích phần xử lý cũ.
  - Chia rows thành các batch theo BATCH_SIZE (default 20).

  1. Batch prediction (LLM gọi 1 lần/batch)

  predict_batch_details(rows):
  - Gộp cả batch thành 1 prompt CSV (qid,question,choices), gọi
  agent_with_batch_confidences() — một lần gọi Ollama (model qwen3.5:4b mặc
  định) cho cả batch, lấy về cả text trả lời và logprobs token-level.
  - Parse câu trả lời theo regex qid,answer mỗi dòng.
  - Dùng extract_confidences() để tính confidence mỗi câu từ logprob của token
  A/B/C/D thực tế trong response (so với top-logprob candidates) → đây là cơ chế
  confidence "thật" dựa trên xác suất model, không phải tự model tự chấm.
  - Nếu batch chỉ có 1 row và không parse được → apply_single_row_fallback cố
  gắng lấy câu trả lời cuối cùng dạng "đáp án: X" bằng regex.

  retry_bad_rows: với row nào ra N/A, gọi lại riêng từng row
  (predict_single_retry) bằng prompt ép buộc trả lời đúng 2 dòng CSV.

  2. Routing per-row — đây là phần lõi, theo đúng thứ tự ưu tiên

  Với mỗi row trong batch, sau khi có ans (từ batch) và conf (logprob
  confidence):

  workflow_v2_answer(row)  ──nếu match──▶ dùng kết quả workflow_v2,
  answer_source = "workflow_v2:<task>"
          │ (nếu None/knowledge/conf thấp)
          ▼
  is_calculation_question(row) + try_calculator/try_code_calculator  ──nếu
  match──▶ answer_source = "calculator", confidence = 1.0
          │ (nếu không phải tính toán)
          ▼
  phân loại theo answer_quality + conf:
    - ans == N/A                      → answer_source = "missing"
    - weak_parse                      → domain_retry (subject-specific prompt)
    - vừa được single_retry từ N/A     → answer_source = "single_retry"
    - conf is None hoặc conf > 0.8     → giữ "batch", chỉ web-search nếu câu hỏi
  "volatile" (giá, CEO, hiện nay...)
    - 0.55 <= conf <= 0.8              → domain_retry (math/physics/it/...)
    - conf < 0.55                      → web search fallback

  2a. Workflow V2 (agents/workflow_v2/) — pipeline mới, chạy TRƯỚC mọi nhánh cũ

  workflow_v2_answer(row):
  1. classify(text, row) — ưu tiên cứng theo thứ tự: retrieval (nếu prompt chứa
  cả "Đoạn thông tin" + "Câu hỏi") > calculation (regex biểu thức/phương trình
  hoặc heuristic: ≥2 số + đơn vị + từ khoá tính toán + options toàn số) >
  knowledge (fallback).
  2. Theo task:
    - retrieval: parse context/question → chunk theo đoạn (\n\n, min 20 ký tự) →
  BM25 (package rank_bm25 nếu có, fallback token-overlap thủ công) lấy top-10 →
  rerank bằng model dengcao/Qwen3-Reranker-4B (mới gắn) lấy top-3 → build
  prompt "chỉ dùng thông tin trong đoạn" → gọi LLM → confidence cố định 0.8.
    - calculation: phân loại arithmetic/equation/word_problem/complex → giải
  bằng ast-safe-eval (arithmetic/equation) hoặc nhờ LLM sinh result = <expr>
  (word_problem/complex) → so khớp với option số gần nhất → confidence theo loại
  + sai số (0.95 arithmetic → 0.6 fallback).
    - knowledge: build prompt CoT có format ANSWER:/CONFIDENCE: → gọi LLM 3 lần
  (temperature 0.7) → majority vote + blend confidence = 0.7*consistency + 
  0.3*avg_self_confidence.
  3. Trong main.py, task "knowledge" bị bỏ qua hoàn toàn (if task == 
  "knowledge": return None) — workflow_v2 chỉ thực sự ghi đè kết quả batch khi
  là retrieval hoặc calculation; knowledge vẫn để các nhánh cũ (domain retry,
  web search) xử lý.

  2b. Calculator cũ (agents/calculator.py)

  Vẫn còn là lưới an toàn thứ 2: regex riêng phát hiện biểu thức/phương trình
  tuyến tính, try_calculator (an toàn, không LLM) hoặc try_code_calculator (sinh
  code, chạy qua agent) — confidence luôn = 1.0 khi match.

  2c. Domain retry (agents/subject_router.py)

  classify_subject gắn câu hỏi vào 1 trong 7 domain
  (it/math/physics/geography/history/english/logic/other) bằng keyword matching,
  có thêm "risk keywords" (ngoại trừ, mâu thuẫn, suy ra...) để biết câu nào dễ
  sai cần double-check bằng domain-specific prompt (prompts/domain_*.md).

  2d. Web search (agents/search_router.py + agents/web_search_graph.py)

  should_search trigger theo VOLATILE_KEYWORDS (giá, CEO, hiện nay, GDP...) hoặc
  khi answer = N/A. Search thực hiện qua LangGraph state machine 3 node: route 
  → search → finalize, dùng WebSearchClient
  (DisabledWebSearch/StaticWebSearch/HttpJsonWebSearch/DuckDuckGo) trả context
  rồi hỏi lại LLM với context đó.

  3. Output

  - pred.csv: chỉ qid,answer.
  - pred_audit.csv: thêm confidence, needs_search, search_used, answer_source —
  cột answer_source cho biết câu trả lời đến từ nhánh nào
  (workflow_v2:retrieval, workflow_v2:calculation, calculator, batch,
  domain_retry_changed/same, single_retry, missing...) — dùng để debug/audit
  chất lượng.

  Điểm cần lưu ý

  - Workflow_v2 hiện không xử lý nhánh knowledge trong main.py dù module
  knowledge.py đã viết đầy đủ (majority-vote 3 samples) — đây có vẻ là quyết
  định thận trọng để giữ pipeline cũ (domain retry + web search) làm chủ lực cho
  câu hỏi kiến thức thuần, chỉ để workflow_v2 đảm nhận phần nó tự tin nhất
  (retrieval có ngữ cảnh rõ, calculation có thể verify bằng số).
  - requirements.txt đang ghi BM25 (sai tên package) thay vì rank_bm25==0.2.2 —
  chưa sửa theo đề xuất trước, vẫn chạy được nhờ fallback token-overlap nhưng
  chưa dùng BM25 thật.
