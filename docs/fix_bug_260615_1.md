## 1. Tổng Quan Sự Cố (Bug Overview)

Khi triển khai hệ thống Atlas Agent trên môi trường Kaggle GPU với vLLM server cục bộ, pipeline LangGraph sụp đổ ngay trong giai đoạn Batch Processing đầu tiên với log lỗi:

```text
[*] LLM config: Base URL=http://127.0.0.1:8000/v1 | Model=Qwen/Qwen2.5-7B-Instruct-AWQ
[*] Hardware mode: GPU | LLM concurrency hint: 8
Router error (1/10): Connection error.
Router error (2/10): Connection error.
...
```

**Hệ quả:** Toàn bộ Batch bị thất bại, không có câu hỏi nào được xử lý, output file rỗng hoặc chứa toàn giá trị mặc định "B".

---

## 2. Phân Tích Nguyên Nhân Gốc Rễ (Root Cause Analysis)

Qua rà soát mã nguồn tại các file `.env`, `docker-compose.gpu.yml`, `entrypoints.sh`, `main.py`, và `src/agent_graph.py`, xác định **3 nguyên nhân gốc rễ** phối hợp gây sự cố:

### 2.1. Lệch pha tên mô hình (Model Name Mismatch)
| Thành phần | Giá trị cấu hình | Tên model sử dụng |
|---|---|---|
| **vLLM Server** (Cell Kaggle) | `--served-model-name` | `qwen-hackathon` |
| **Client Python** (`agent_graph.py`) | `LLM_MODEL_NAME` default | `Qwen/Qwen2.5-7B-Instruct-AWQ` |

> Server vLLM khi được khởi động với cờ `--served-model-name qwen-hackathon` sẽ **chỉ chấp nhận** request có `model="qwen-hackathon"`. Bất kỳ request nào gửi với tên model khác (ví dụ: `Qwen/Qwen2.5-7B-Instruct-AWQ`) sẽ bị server trả về **HTTP 404 Model Not Found**, mà phía client nhận được dưới dạng `Connection error` hoặc parse error.

### 2.2. Race Condition khởi động (Startup Race Condition)
- vLLM cần **1-3 phút** để nạp model 7B vào VRAM.
- Trong `entrypoints.sh`, nhánh `vLLM` **không có health check** (chỉ Ollama mới có `until curl...`).
- `main.py` chạy ngay lập tức, nã 8 luồng concurrency vào port 8000 trong khi port chưa mở → `Connection Refused`.

### 2.3. Custom Retry quá yếu (Insufficient Backoff)
- Vòng lặp retry trong `router_node`, `python_repl_node`, `reasoning_node` chỉ chờ `1 giây` giữa các lần thử.
- Với 10 lần retry × 1s = **tổng thời gian chờ tối đa ~10 giây**, hoàn toàn không đủ cho vLLM khởi động xong.
- Đồng thời, `ChatOpenAI` không được cấu hình `max_retries` và `timeout`, khiến HTTP client bỏ cuộc quá sớm.

## 3. Chi Tiết Giải Pháp Xử Lý (Resolution Details)

### 3.1. Đồng bộ tên mô hình → `qwen-hackathon`
- Sửa giá trị mặc định của `LLM_MODEL_NAME` từ `"Qwen/Qwen2.5-7B-Instruct-AWQ"` thành `"qwen-hackathon"`.
- Đảm bảo khớp hoàn toàn với `--served-model-name` trên vLLM server.

### 3.2. Tăng cường sức bền HTTP Client
- Bổ sung `max_retries=5`: Cho phép tầng HTTP (httpx/openai SDK) tự động retry 5 lần khi gặp lỗi tạm thời (Connection Refused, 503, 429...).
- Bổ sung `timeout=120.0`: Tăng thời gian chờ phản hồi lên 120 giây, phòng trường hợp model suy luận Chain-of-Thought cho câu hỏi phức tạp tốn nhiều thời gian inference.

### 3.3. Áp dụng Exponential Backoff cho toàn bộ Custom Retry Loop
- Thay thế `await asyncio.sleep(1)` bằng `await asyncio.sleep((attempt + 1) * 2)`.
- Chuỗi thời gian chờ mới: **2s → 4s → 6s → 8s → ... → 20s** (tổng ~110s cho 10 lần retry).
- Áp dụng đồng nhất tại 3 node: `router_node`, `python_repl_node`, `reasoning_node`.
